# Unit 2: Requirements and Modelling

## 10 Golden Points
1. RE steps: Inception, Elicitation, Elaboration, Negotiation, Specification, Validation, Management
2. Functional requirement is what the system does, non functional is how well it does it, domain requirement is a rule of the field
3. Elicitation techniques: interview, questionnaire, brainstorming, JAD, scenario, mind mapping
4. Use case diagram has actor, use case, system boundary, association, include and extend
5. SRS as per IEEE 830 has 3 big parts: Introduction, Overall description, Specific requirements
6. SRS quality is CUCCRVMT: Correct, Unambiguous, Complete, Consistent, Ranked, Verifiable, Modifiable, Traceable
7. Three views of modelling: static is ER diagram, functional is DFD, dynamic is state transition diagram
8. ER diagram has entity, attribute, relationship and cardinality 1 to 1, 1 to N, M to N. M to N becomes a separate table
9. DFD has external entity, process, data flow and data store. Level 0 is the context diagram, level 1 opens the process
10. State diagram has states, events and transitions. Data dictionary uses equals, plus, brackets, parentheses and braces

## Worked calculations

### Scene 4: Actor + Use case (oval) + Boundary + Association + Include + Extend
    ## Use case scenario: Place order
    Actor: Customer
    Pre: logged in, cart not empty
    Main flow: 1 review cart 2 enter address
    3 make payment 4 order confirmed
    Alternate: payment fails -> retry or cancel
    Post: order saved, email sent
    ~ include = must happen, extend = optional

### Scene 5: SRS qualities: CUCCRVMT = Chuck Uses Catapult, Chuck Rocks, Venom Meets Terence
    ## 8 quality characteristics
    Correct | Unambiguous | Complete | Consistent
    Ranked | Verifiable | Modifiable | Traceable
    ## Importance of SRS (mid 3a)
    1 Contract between client and team
    2 Base for design, coding and testing
    3 Reduces rework and cost
    4 Base for estimation and planning
    5 Reference for maintenance

### Scene 7: Entity = rectangle, Relationship = diamond. M:N = alag table
    ## Attributes (PK = primary key, FK = foreign key)
    Department(dept_id PK, name)
    Professor(prof_id PK, name, dept_id FK)
    Course(course_id PK, title, credits, dept_id FK, prof_id FK)
    Student(student_id PK, name, email, dept_id FK)
    ## Relationships
    Dept 1:N Professor, Dept 1:N Course, Dept 1:N Student
    Professor 1:N Course (teaches)
    ! Student M:N Course -> Enrollment(student_id, course_id, grade)

### Scene 9: Data dictionary: = hai, + aur, [ | ] ya, ( ) optional, { } repeat
    ## Examples
    Name = First + (Middle) + Last
    Address = House + Street + City + PIN
    Seat_class = [ Economy | Business | First ]
    Passengers = 1 { Passenger } 6
    ## Process specification
    Structured English: IF seat free THEN book ELSE waitlist
    Or decision table, or decision tree
